# Changelog

## Unreleased

- Fixed the pet page going completely inert when the clock has never synced (fresh flash or no Wi-Fi): actions and mini-games were gated on SNTP time sync even though they don't need a clock — only the decay settlement does. The gates are gone, and with no synced clock the growth stage is derived from the already-accumulated age instead of rendering a hatched pet back as an egg. Mood likewise comes from the stats instead of showing "—". Covered by a new host test for the unsynced-stage fallback.

- Added Tamagotchi-style mini-games to the pet: in action mode, picking Play now opens a small game menu with two classics — Guess (the pet hides behind one of two doors; pick left/right and it peeks out; five rounds, the traditional Tamagotchi pastime) and React (an apple appears at a random moment; press OK within 900 ms; early presses count as a foul). Winning rounds raise mood (and a gram of weight each); starting a game costs 10 energy, so a tired pet refuses to play. Results persist with the pet state, and the score line tracks rounds live.

- Added the teleprompter (M5) with page-turn sync. Speech scripts come from the portal's new "Notes" section as plain UTF-8 text with **one line = one segment** (one PPT page), stored as `notes.txt` (32 KB cap) in the store partition; three input paths share that pipeline: direct paste, .txt upload, and .pptx speaker-note extraction done entirely in the phone browser (a dependency-free ZIP directory walk plus the built-in DecompressionStream inflates each `ppt/notesSlides/notesSlideN.xml` and collects its text runs — no CDN access needed on the captive network, no parsing on the device). On the badge, the Prompter menu page shows the current segment in large text with an i/N progress bar and runs the same BLE keyboard as the page turner: in linked mode ▲/▼ send Page Up/Down to the computer and step the local segment in lockstep (slides and notes stay aligned with zero host software); in auto mode the text scrolls at an adjustable speed and rolls into the next segment on its own (▲/▼ adjust speed, OK double-press pauses). Factory reset now also deletes the saved script. Segment splitting is a pure module with host tests, and the pptx extraction path was verified end-to-end against a generated .pptx in Node. Also fixes a portal JavaScript syntax error (a lost string-concatenation operator) that broke the whole provisioning page since the QR-slot form landed earlier in this cycle.

- Fixed the Turner page showing "BLE failed": the Bluetooth host needs ~40 KB of heap, but the initialized Wi-Fi driver leaves only ~38 KB, so NimBLE startup failed on every entry. Following the original radio-exclusivity design, entering the Turner page now suspends the Wi-Fi pulse (the driver is stopped and deinitialized to free its memory), and leaving the page re-initializes Wi-Fi and resumes the hourly pulses; the interruptible pulse loop keeps suspend wait ~1 s. Bluetooth advertising as "BadgeBot" was verified on hardware.

- Fixed the clock showing UTC instead of local time (e.g. 05:15 when it was 13:15 in Beijing; the date stayed right because both fell on the same day): the code set the China Standard Time zone (`TZ=CST-8`) in `app_clock_init()`, but that function was never called. It now runs during boot, and the sync log line prints the resulting local time and zone for easy verification. Also fixed the Turner menu entry showing as `[FAIL]` and being unenterable — its readiness flag was never set.

- Added the BLE page-turner (M3): the badge now advertises as a Bluetooth keyboard named "BadgeBot" (HID-over-GATT service implemented on NimBLE — IDF 5.5 ships no HID-device example). After pairing from the computer's Bluetooth settings, the arrow keys send Page Up/Page Down so slides, PDFs, and readers can be driven with no host-side software; the status-bar Bluetooth icon lights up when a host is connected. OK on the Turner page switches the key mapping between PgUp/PgDn (presentations) and Left/Right arrows (image viewers, manga), persisted in NVS (`hidmap` config key). Pairing is Just Works with LE Secure Connections and bonding persisted in NVS, so hosts re-connect automatically after a badge reboot; stale keys from a wiped device are handled by deleting the old bond on repeat pairing.

- Reworked the pet layout keys so actions are reachable: on the pet page, OK long-press now toggles an action mode (highlighted, with an "action:" line showing the selection) instead of opening the menu, which previously swallowed every key press and could leave the page only through the menu. In normal mode the arrows switch layouts and OK short-press opens the menu as on other pages; in action mode the arrows pick feed/play/clean/sleep-wake and OK performs it.

- Added a factory-reset row to settings (replacing the firmware-version row): the first OK press arms it ("press OK again"), a second press erases NVS configuration and pet data, deletes uploaded avatar/QR images, restores the default theme, and rebuilds the page; navigating to another row disarms it.

- Expanded QR codes to four slots on the badge QR layout (2×2 grid of 96 px codes). Each slot is independently configured in the portal as either generated from text (rendered on device) or an uploaded image (binarized to 128×128, stored as `qr0.img`…`qr3.img`), with a per-slot caption shown under the code (defaulting to QR1…QR4). The portal gained a four-slot form (caption, generated/uploaded radio per slot, text or crop-upload per slot) with new `/api/qr0`…`/api/qr3` upload endpoints; the config API now carries `qr_text`/`qr_label` arrays plus a `qr_mode` bitmask. The LVGL memory pool grew 48→64 KB so four on-device generated codes fit.

- Removed the GitHub contribution heatmap: the device TLS layer could not complete RSA signature verification for any chain, and the feature is parked until that is root-caused. Removal frees ~165 KB of flash (the app is now 34%% free). In its place, the pet card became a real Tamagotchi-style pixel pet: an egg hatches after two minutes into baby, child, and adult stages (black-and-white bitmap sprites with two-frame idle animation); hunger, mood, cleanliness, and energy decay over real time with offline settlement capped at three days; droppings appear periodically and need cleaning; sleeping restores energy. State persists in NVS and survives reboots. Home layouts are now three (card / QR codes / pet).

- Fixed avatar uploads failing with "write failed": FATFS long-filename support was disabled, and the 96×96 avatar filename exceeds the 8.3 short-name limit (the QR-image filename happened to fit, which is why only avatars failed). The provisioning portal also gained a manual square-crop editor (draggable, resizable selection centered on the subject), a 10-second heartbeat line that shows the remaining hotspot time and turns red when the device is unreachable, and clear success/failure coloring on every action.

- Reworked the heatmap fetch for constrained memory: the public contributions API returns ~255 KB per user, which is now streamed through a 2 KB rolling-window parser into the 371-byte NVS cache instead of being buffered whole; the fetch waits for SNTP time sync before connecting and retries once. Large badge-page buffers are now sized per layout. Known issue: server-certificate verification currently fails deterministically on this device for every TLS chain (RSA operations), so the fetch keeps the placeholder page until that is root-caused; the failure is graceful and cached data still renders.

- The provisioning portal now keeps the hotspot open after saving Wi-Fi so avatar/QR uploads and profile edits can continue; a prominent "Finish & connect" button closes the hotspot on demand and the badge immediately goes online to sync time and fetch the heatmap. Every form action shows visible success (green) or failure (red) feedback, image decode failures are reported, and the page gained a Chinese/English toggle. Uploads remain strictly center-cropped to a square (96×96 avatar, 128×128 black-and-white QR image), which the labels now state.

- The device UI gained a language setting (Chinese/English) covering the menu, settings rows and values, key hints, and static page texts (user-entered content is always shown as typed). The GB2312 font subsets are now built from a symbol list that automatically includes every non-ASCII character used in the UI sources, fixing glyphs that silently failed to render (previously some level-2 characters, e.g. the one in "liulan" / browse, were missing).

- Added a fourth badge home layout, the pet card (large mascot with mood placeholder), alongside card, dual QR, and GitHub heatmap. Settings now offers a layout sub-page where each layout can be enabled or disabled individually (at least one must stay on); the badge page cycles only through enabled layouts. The heatmap layout refreshes by itself once the device fetches data.

- Expanded the provisioning portal and the badge home page. The hotspot now uses a random SSID and password each session (scan the on-screen QR to join instead of typing). The portal form adds phone-side image upload for the card avatar (center-cropped to 96×96) and a second QR image such as a WeChat card (binarized to 128×128), plus a GitHub username field; uploads are stored in the FATFS `store` partition. The badge home page now offers three switchable layouts: card (uploaded avatar or mascot, name/organization/title), dual QR (generated from the configured link plus the uploaded image), and a GitHub contribution heatmap (53×7) fetched by the device itself from a public contributions API during its Wi-Fi pulse and cached in NVS. The clock shows only on the card layout.

- Networking fixes: the device now pulses Wi-Fi once at boot instead of waiting up to an hour, so time sync and heatmap data refresh shortly after power-on; Wi-Fi driver RX buffers were trimmed (10→6 static, 32→16 dynamic) and large badge-page image buffers moved from static storage to on-demand allocation, fixing a boot-time `esp_wifi_init` out-of-memory that left the device offline until the next portal save (init now retries instead of giving up).

- Reworked the shared UI: every screen now carries a top status bar (battery gauge, volume, Wi-Fi and Bluetooth icons) and a bottom key-hint bar where key caps with a thick border mean long press and a thin border mean short press. Added a light and a dark theme (extensible palette roles, persisted in NVS, switchable in settings), Chinese labels for the settings page and key hints rendered through a new 16 px CJK font, global auto screen-off with wake-on-any-key (the waking key press is not dispatched), manual screen off via long-press DOWN on the badge page, and a paginated menu that no longer rebuilds its screen when flipping pages. Mascot animations are now stopped before their screens are deleted, fixing a use-after-free that displaced the menu mascot.

- Added a badge home page and a settings page. The badge page shows the configured name, organization, and title (with a hide toggle), a battery gauge, and a clock placeholder, and turns the backlight off after a configurable idle time. The settings page adjusts brightness, volume, home layout, screen-off delay, and boot page; all settings persist in NVS. User text renders with a new 20 px 1-bpp CJK bitmap font (ASCII + GB2312 level-1). The menu is now paginated, and the device boots into the badge page by default.
